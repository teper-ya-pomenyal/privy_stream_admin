# Handoff: privy_stream — админка владельца узла (вариант B · TABS)

## Overview

Отдельное приложение для **владельца узла** privy_stream: следит за здоровьем своих сервисов, заливает и индексирует релизы, правит метаданные каталога, управляет пользователями, их refresh-сессиями, метками 18+ и смотрит логи gRPC/Gateway. Работает только с одним узлом — своим (в отличие от клиента, где узлов много).

Выбран **layout B — горизонтальные табы** под шапкой, контент во всю ширину с `max-width: 1320px` по центру. Платформы: десктоп (основная) + мобильный вид (референс, см. раздел Mobile).

Рекомендуемый стек — тот же, что у клиента: **Vite + React + TypeScript** (веб-приложение, раздаётся самим Gateway по отдельному пути, например `/admin`, либо Tauri, если нужен десктоп-бинарь). Бэкенд — Go (user_service, catalog_service, streaming_service, gateway). Все данные в макете — моки; нужны admin-эндпоинты в Gateway (список ниже).

## About the Design Files

`Privy Stream Admin.dc.html` — **дизайн-референс в HTML**, а не продакшн-код. Задача — воссоздать дизайн в целевом окружении по его правилам (компоненты, роутинг, стили, стейт), а не встраивать HTML.

Файл — компонент со шаблоном и классом логики: разметка эквивалентна JSX (атрибуты camelCase, `style="…"` → объект стилей), `<sc-for list as>` = `.map()`, `<sc-if value>` = условный рендер, `{{ x }}` = значение из `renderVals()`. Класс логики — React class component без `render()`. Перенос в `.tsx` механический.

Открыть: `Privy Stream Admin.dc.html` и `support.js` рядом, через локальный сервер (`npx serve .`). В бандле по умолчанию включён layout B; переключатель `LAYOUT A/B/C` и `DESKTOP/MOBILE` в шапке — витрина макета, **не переносить**.

## Fidelity

**High-fidelity.** Цвета, типографика, отступы и состояния — финальные. Визуальный язык полностью совпадает с клиентом (см. `design_handoff_privy_stream/README.md`): тёмная тема, Manrope + IBM Plex Mono, акцент `#D8452B`, без радиусов и теней. Обложки в каталоге — плейсхолдеры (цветной квадрат `oklch(0.34 0.07 {hue})` с инициалами `oklch(0.82 0.06 {hue})`); в приложении — реальный арт, плейсхолдер остаётся состоянием загрузки/отсутствия.

### 5. Сессии (refresh-токены)

- Тулбар: чипы `ВСЕ` / `АКТИВНЫЕ` / `ОТОЗВАННЫЕ`; если пришли с экрана пользователей — чип-фильтр `{login} ×` (фон `#E8E6E1`, текст `#0B0B0C`). Справа опасная кнопка `ОТОЗВАТЬ ВСЕ, КРОМЕ ТЕКУЩЕЙ`: рамка `#D8452B`, текст `#F0765C`, hover фон `rgba(216,69,43,.12)`.
- Строка (flex-wrap, `padding: 15px 0`, отозванная — `opacity: .55`):
  - Блок 1 (`flex: 1 1 210px`): пользователь Mono 600 13px, для своей сессии — метка `ЭТА СЕССИЯ` (Mono 600 9px `#8DB36B`); ниже `{устройство / user-agent} · {IP}` Manrope 400 11px `#A8A6A0`.
  - Блок 2 (`flex: 1 1 170px`, Mono 400 10px `#6E6C67`): `семья {id} · ротация #{n}` (id семьи `#C8C6C0`, сокращён до `f7a2…c91e`); `активность {когда} · истекает {через}`.
  - Блок 3: статус-бейдж `АКТИВНА` (`#8DB36B`) / `REUSE` (`#D8452B`) / `ОТОЗВАНА` (`#4E4C48`) + кнопка `ОТОЗВАТЬ` (нет у текущей и неактивных).
  - Для `REUSE` — строка на всю ширину Mono 400 11px/1.5 `#F0765C`: «Повторное предъявление уже ротированного refresh-токена — вся семья отозвана автоматически.»
- Модель под user_service: сессия = **семья refresh-токенов** (family id); каждая ротация увеличивает счётчик; предъявление старого токена семьи → отзыв всей семьи и событие `REUSE`. Отзыв из админки = удаление семьи из `redis_users_sessions`.

### 6. Метки 18+

Принцип: метка **не скрывает** контент — только ограничивает показ аккаунтам младше 18 (по дате рождения). Так и сформулировано в подписи экрана.

- Чипы: `ОЧЕРЕДЬ` / `РЕШЁННЫЕ` / `ВСЕ`.
- Строка (flex-wrap, `padding: 15px 0`):
  - Трек Manrope 600 14px; `{артист} · {релиз}` Mono 400 10px `#6E6C67`.
  - Источник (`flex: 0 0 150px`): Mono 600 10px `.1em` `#A8A6A0` — `ТЕГ EXPLICIT` (из тегов при индексации), `ЖАЛОБА` (от пользователя), `ТЕКСТ` (совпадение по словарю); деталь Mono 400 10px `#4E4C48` (`ID3 · ITUNESADVISORY=1`, `от marta_v · 2 д назад`…).
  - Действия в очереди: `ПОМЕТИТЬ 18+` (акцент, `padding: 9px 12px`) и `БЕЗ МЕТКИ` (обводка). После решения — бейдж результата (`18+` красный / `БЕЗ МЕТКИ` серый) и ссылка `ВЕРНУТЬ` (обратно в очередь).
- Пометка должна выставлять `explicit` на треке в каталоге (тот же флаг, что тумблер в редакторе каталога).

### 7. Логи

- Тулбар: чипы сервиса `ВСЕ`, `GATEWAY`, `USER`, `CATALOG`, `STREAM`; вертикальный разделитель 1×22 `#26262A`; чипы уровня `ВСЕ УРОВНИ`, `WARN+`, `ERROR`; справа (`margin-left: auto`) тумблер `LIVE` / `ПАУЗА` — чип с точкой 6×6 (`#D8452B` мигает 1.4s в LIVE, `#4E4C48` на паузе).
- Панель: фон `#0E0E10`, `border: 1px solid #1E1E22`, Mono 400 11px/1.45. Строка: `display: flex; flex-wrap: wrap; gap: 2px 14px; padding: 7px 12px; border-bottom: 1px solid #151518`:
  - время `HH:MM:SS` `#4E4C48`;
  - уровень (40px, 600): INFO `#6E6C67`, WARN `#D9A441`, ERROR `#D8452B`;
  - сервис (118px) `#8E8C86`;
  - сообщение `#C8C6C0` (`flex: 1 1 260px`, `overflow-wrap: anywhere`) — gRPC-метод (`/user.v1.UserService/Login`) или HTTP (`POST /v1/auth/login`);
  - код: `OK`/`2xx` — `#6E6C67`; `5xx`/`Internal`/`Unavailable` — `#D8452B`; прочее (`Unauthenticated`, `401`…) — `#D9A441`;
  - длительность `{n}ms` `#6E6C67`, 50px справа.
- Новые записи добавляются сверху; буфер 200 (на экране — 80, мобильный — 40). «Нет записей по фильтру.» — пустое состояние.
- В приложении: источник — logging-интерсептор gRPC (unary/stream) в каждом сервисе + middleware chi в Gateway, стрим в админку через SSE/WebSocket.

## Interactions & Behavior

- **Навигация:** табы; счётчики обзора → свои экраны; карточка сервиса → Логи с фильтром; «ОТКРЫТЬ →» в хранилище → Релизы; «ВСЕ ЛОГИ →» → Логи без фильтров; `{n} сесс. →` у пользователя → Сессии с фильтром по логину. Роуты: `/admin`, `/admin/releases`, `/admin/catalog/:id?`, `/admin/users`, `/admin/sessions?user=`, `/admin/moderation`, `/admin/logs?svc=&lvl=`.
- **Опасные действия** (отозвать все, блок) в макете выполняются сразу с тостом. В приложении добавить подтверждение для `ОТОЗВАТЬ ВСЕ, КРОМЕ ТЕКУЩЕЙ` и блокировки.
- **Hover:** обводка → рамка `#4A4A50`, текст `#E8E6E1`; акцент → `#F0563A`; строка → фон `#131316`; карточка → рамка `#3A3A40`; текст-ссылка → `#E8E6E1`.
- **Анимации:** `pv-blink` — `0%,45% {opacity:1} 50%,100% {opacity:.15}` для статус-точек (1.4–1.8s infinite). Прогресс загрузки — `transition: width .4s`.
- **Нужные, но отсутствующие в макете состояния:** скелетоны списков, ошибка запроса (инлайн «код · сообщение» в стиле клиента: фон `rgba(216,69,43,.1)`, `border-left: 2px solid #D8452B`, Mono 500 11px `#F0765C`), ошибка индексации файла (стадия `ОШИБКА` красным + причина, кнопка повтора), конфликт при сохранении метаданных, пустые списки пользователей/сессий.

## State Management

- `screen` → роутер.
- Обзор: `services[]` (name, proto, latency, uptime, status, note) — поллинг раз в 5–10 с; счётчики — производные.
- Релизы: `queue[]` (id, name, size, progress, stage, tags{title, n, artist, dur, explicit}, isCover); `draft` {title, artist, year, type, tracks[], coverFileId}. Черновик стоит хранить на сервере (чтобы пережил перезагрузку).
- Каталог: `albums[]` (id, title, artist, year, genre, type, tracks[{id, title, dur, explicit}]), `query`, `filter`, `edit` — локальная копия выбранного релиза.
- Пользователи: `users[]` (id, login, birthDate, role, createdAt, blocked), `query`.
- Сессии: `sessions[]` (id, user, device, ip, familyId, rotation, lastUsed, expiresAt, status: ACTIVE|REUSE|REVOKED, current), `filter`, `user`.
- Метки: `items[]` (id, trackId, source, detail, state: pending|marked|cleared), `filter`.
- Логи: `logs[]` кольцевой буфер 200, `svc`, `lvl`, `live`.
- Вид: `layout` и `device` — только витрина макета, выбросить.

**Admin API (предложение для Gateway, все под ролью OWNER):**
`GET /v1/admin/health` · `POST /v1/admin/uploads` (multipart/tus) · `GET /v1/admin/uploads/events` (SSE) · `GET|POST|PATCH /v1/admin/releases[/:id]` · `GET /v1/admin/users` · `PATCH /v1/admin/users/:id` (blocked) · `GET /v1/admin/sessions` · `DELETE /v1/admin/sessions/:familyId` · `POST /v1/admin/sessions/revoke-others` · `GET /v1/admin/moderation` · `PATCH /v1/admin/moderation/:id` · `GET /v1/admin/logs/stream` (SSE). Роль `OWNER` должна попадать в claims access-токена (RS256), проверка — middleware в Gateway.
